## 1. 要做什么

一个 Claude Code 插件，把**扫描件 / 截图**变成**可引用原文的 klode 知识库**。图书和医疗单据共用一套底层，医疗只加单据语义。

用户的原始要求（2026-10-12，整理后）：

1. 抽象出共同框架，先落地医疗库；最终产出 **skill、agent、plugin、workflow 四件套**，带测试用例，用 TDD 实现；先给用户确认概要计划。
2. 用 wua skill 画常用场景、用户用例与工作流，用户确认后再出 TDD 详细计划。
3. OCR 双模型审计抽象出来；图片还要发给 **Claude Opus 最高档**和 **Codex 最高档**读图，**四路互相比对**。
4. 确认方式：本地 HTML 页逐条点选。备份：数据项目本地 git + 外置盘裸仓。
5. `/kb-build` 必须包含**书架和书桌**机制，并且**全部自动化**。

## 2. 已定的设计（来自概要计划 v1，已在私有项目里画过三张 WUA 图）

**分层**

| 层 | 内容 | 位置 |
|---|---|---|
| 通用 `klode-kit` 插件（本仓） | `/kb-ocr`（多引擎读图）、`/kb-audit`（字段比对 + 确认页 + 写回）、`/kb-build`（导出 txt → 书架 → 书桌 → agent → MCP 登记）、`/kb-check`（门禁） | 本仓 |
| 医疗层 | 单据登记、front-matter 契约（labs / meds 三元组）、脱敏导出、`/med-intake` 入口 | 代码在本仓（可选模块），**数据与真实运行在私有项目** |
| 图书层 | 切章、页码模型 | 现有 189 项目 |

**四路读图**：A Apple Vision（zh-Hans + ja）、B Unlimited-OCR MLX（tesseract 兜底）、C Claude Opus、D Codex（`codex -i <图>`）。
统一输出 JSONL：`{engine, page, line, text, fields:[{kind, value, bbox}]}`，`kind ∈ number|date|drug|unit|flag`。
外发云端前可选**抬头打码**（Vision 定位姓名 / 编号区域后涂黑）。

**审计回路**（9 步，唯一人工步骤是点选）：打码 → 本机两路 → 云端两路 → 抽字段 → 字段比对（参照引擎弱点白名单）→ 裁分歧小图 → 生成确认页 → 用户点选 → 写回记录（`uncertain` 非空不得标 verified）。
原则：**分歧只呈现、不自动改字**；三路一致一路不同时，多数值只是推荐值。

**/kb-build 自动链**（9 步，零人工）：脱敏导出 txt → `klode build`（只出 L0 骨架）→ 写卡 + `verify` 每条锚点 → 书桌维度 → `diagnose` 路由测试（≥4/5）→ 生成 expert agent → 登记 registry + MCP → MCP 烟雾测试 → `klode check --strict` 0/0。
三条回路：路由不足回书桌、引文非 FOUND 回 agent、锚点失效回写卡。

**agent 两个**：`kb-verifier`（只读，对照原件判 verified / disputed）、`<kb>-expert`（查询专家，经 MCP）。
