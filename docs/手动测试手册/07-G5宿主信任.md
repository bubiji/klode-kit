# T07 G5 宿主信任

层：2 合成数据亲手验　闸门：G5（接受工作区信任）　时间：5–10 分钟　花费：0（只打开 `claude` 的信任对话框，不提问、不调用模型）

## 目的

Claude Code 对每个目录有「工作区信任」。官网（见 `docs/install.md` 第 6 节）说明：交互会话在没信任过的目录里启动时会弹出信任对话框；项目 `.claude/settings.json` 里的 `permissions.allow` 规则和项目 `.mcp.json` 里的 MCP 服务器，**只有接受信任之后才生效**；而 `claude -p`（非交互）永远不弹这个框。所以：

- 没有人在数据项目里交互运行一次 `claude` 并点「信任」，后面的发布登记（`.claude/settings.local.json` 的批准）、专家 agent 的 MCP、Workflow 的 Bash 权限都不会生效，自动化也无法替你点。
- `klode-kit doctor --project <数据项目>` 会检查这一点（`project_trust` 一项）。检查是**只读**的：读 `~/.claude.json` 里该目录的 `hasTrustDialogAccepted`，从不写它。

这一项让你亲手确认：对话框怎么出现、点了之后 doctor 怎么变、宿主对 MCP 的态度怎么跟着信任变化。其他章节（03、04、06、05）都依赖它。

## 前提

- T01 通过，`claude` 可以交互运行。
- 一个演示目录 `<演示目录>`（空目录即可）。**不要在家目录里做这个测试**：官网说在家目录直接启动时，信任只在当次会话有效、不写入磁盘，doctor 也把家目录判为不信任。

## 步骤

### 7.1 基线：没接受信任时 doctor 怎么说

```sh
export KK=<klode-kit 目录>
export DEMO=<演示目录>
mkdir -p "$DEMO/trust-demo" && cd "$DEMO/trust-demo"
git init -q .
printf '%s\n' _work/ _raw/ _masked/ _mask_review/ _private/ work/ > .gitignore
"$KK/bin/klode-kit" doctor --project . > /dev/null
echo $?
```

标准错误里应该看到：

```
doctor: MISSING project_trust [project]: workspace trust not accepted for .
  fix: 在数据项目目录交互运行一次 claude 并接受工作区信任（R2-07）: cd '.' && claude
doctor: 1 item(s) missing -> exit 40
```

退出码 40，且**只缺这一项**（因为 `.gitignore` 已按要求写好）。

### 7.2 接受信任

```sh
claude
```

在 `trust-demo` 目录里启动。应该出现一个询问是否信任这个文件夹中的文件的对话框（对话框的具体措辞随 Claude Code 版本而不同，待核）。选择信任 / Yes。进入会话后**什么都不要问**，直接输入 `/exit` 退出。

### 7.3 再看 doctor

```sh
"$KK/bin/klode-kit" doctor --project .
echo $?
```

应该看到 `project_trust` 不再缺：`doctor: all <N> checks passed`，退出码 0（N 是机器段 16 项加项目段 4 项；具体数字以实际为准，待核）。

### 7.4 看信任到底记在哪（只读，不要整份打印）

`~/.claude.json` 里有你的很多私人信息，**不要 `cat` 它、不要贴出来**。只读那一个键：

```sh
python3 - <<'EOF'
import json, os
d = json.load(open(os.path.expanduser("~/.claude.json")))
p = os.path.realpath(".")
print(p.replace(os.path.expanduser("~"), "~"), d.get("projects", {}).get(p, {}).get("hasTrustDialogAccepted"))
EOF
```

应该看到目录路径后跟 `True`。如果是 `None`，说明记录的键不是这个路径（见常见问题里的「git 仓库根」「符号链接」）。

### 7.5 信任与规则：git 仓库根、子目录、非 git 目录（可选）

doctor 的判定规则（来自源码说明）：

- 在 git 仓库里，信任的键是**仓库根**；仓库的子目录与仓库根共用一个键。
- 不在 git 仓库里，键就是该目录本身；**上级目录被信任不算数**。
- 家目录永远判为不信任。
- 设置了 `CLAUDE_CONFIG_DIR` 且没有显式给出存储位置时，检测不到，按「未通过」处理并给出同一条提示（有意保守）。

可以这样验证第一、二条（第三条你本来就别在家目录里做）：

```sh
mkdir -p sub/dir
"$KK/bin/klode-kit" doctor --project sub/dir > /dev/null; echo $?
```

在 7.3 之后，应当退出码 0：子目录跟着仓库根被信任。（待核：本次编写没有实际跑过这一步，请以你的结果为准并在报告里写明。）

```sh
mkdir -p "$DEMO/plain-dir"      # 不是 git 仓库
"$KK/bin/klode-kit" doctor --project "$DEMO/plain-dir" > /dev/null; echo $?
```

应当退出码 40 且缺 `project_trust`：`$DEMO` 即使被信任，也不涵盖 `plain-dir`。（同样待核。）

### 7.6 宿主对 MCP 的态度随信任变化（需要先做完 T04 的发布）

这一步对应自动化里的 `test_trust_probe`。只读命令，不调用模型：

```sh
cd "$DEMO/rxdemo"
claude mcp get rxdemo-klode
```

已信任、且 `.claude/settings.local.json` 里批准过的情况下，应该看到（取自维护者在 Claude Code 2.1.285 上的录制）：

```
rxdemo-klode:
  Scope: Project config (shared via .mcp.json)
  Status: ✔ Connected
  Type: stdio
  Command: <启动器绝对路径>
  Args: ...
  Environment:
    KLODE_KIT_BUILD=b-...
```

对照实验：把 `rxdemo` 整个**复制**到一个没有接受过信任的位置再运行同一条命令：

```sh
cp -R "$DEMO/rxdemo" "$DEMO/rxdemo-untrusted"
cd "$DEMO/rxdemo-untrusted" && claude mcp get rxdemo-klode
```

应该看到 `Status: ⏸ Pending approval (run \`claude\` to approve)`：同一份批准在没有信任的目录里不生效。（复制出来的目录里 `.mcp.json` 仍指向原来的库路径，这里只看状态行。做完把 `rxdemo-untrusted` 移走。）

### 7.7 klode-kit 仓库根的信任（为第 5 章准备）

```sh
cd <klode-kit 目录>
claude          # 接受信任后 /exit
```

宿主测试用的实验目录 `tests/host/_lab/` 在这个仓库里，信任的键是仓库根，所以接受一次就够。不做第 5 章可以跳过。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 接受了信任，doctor 还是报 `project_trust` | 检查 7.4：键是仓库根的**真实路径**。在 git 仓库的子目录里启动，键是仓库根；用了符号链接或 macOS 的 `/tmp`（实为 `/private/tmp`）时，路径以真实路径为准（待核：不同写法的实际记录情况）。在你实际要用的那个目录（数据项目的根）里启动 `claude`。 |
| doctor 提示检测不到信任 | 设置了 `CLAUDE_CONFIG_DIR`，或 `~/.claude.json` 不存在 / 读不了。doctor 对检测不到按未通过处理，这是有意的。取消该变量后重试。 |
| 在家目录里启动 `claude` 接受了信任，doctor 仍报缺 | 家目录的信任不写盘，doctor 也永远判它不信任。换到专门的数据项目目录。 |
| 改了数据项目的目录名后又缺信任 | 信任记在旧路径上。在新路径下再接受一次。 |
| 非交互环境（`claude -p`）里 MCP 一直 pending | `-p` 不弹信任框。必须先在同一目录交互运行一次。 |
| 不想弹框 | 不要关闭：信任是安全机制，本项目依赖它。 |

## 费用与隐私

- 0 美元。只启动 `claude` 的界面，不提问；doctor 只读 `~/.claude.json` 的一个键。
- 报告里**不要贴** `~/.claude.json` 的任何内容（含你所有项目的路径和账号信息）。7.4 只贴那一行输出，且把家目录换成 `~`。
- 结束后把 `$DEMO/trust-demo`、`$DEMO/rxdemo-untrusted` 移走（不要删）。信任记录会留在 `~/.claude.json` 里，那是 Claude Code 自己的文件，请不要手动改它。
