# T08 真实数据试点

层：3 真实数据试点　闸门：G3（发布）、G5（信任，视路线而定）；本章默认**不走 G2**（只开本地路线，不外发）　谁来做：数据主人本人，在自己的私有数据项目里　时间：一批单据 10–60 分钟（取决于要点选的分歧数）　花费：0（本地路线不调用任何模型 API）

## 目的

前 7 章全部用合成样本。合成样本是我们自己画的：字体干净、版式规整、方向端正。真实单据不是这样：手机门户截图、多张截图拼成的长图、带文字层的 PDF、灰色表头条、表格线、稀疏的两栏版式。

本章让数据主人在**自己的私有项目**里，用真实单据把 med-intake 从入库到写回走一遍，回答三个问题：

1. 流程能不能跑通，有没有哪一步**悄悄丢数据**（报成功、实际没记录）。
2. 要人点的分歧有多少条，是不是一个人点得完的量。
3. 写回的记录和原件对不对得上。

维护者第一次做这个试点（2026-10-31，一次住院期间的 28 份化验单、33 页），合成数据没暴露过的缺陷一次就查出了 7 个。结论和修法写在仓库的 `docs/pipeline/20261022-klode-kit/10-真实数据试点记录.md`。所以这一章最有价值的产出是**你发现的新问题**。

## 前提

- T01 通过（`bin/klode-kit doctor` 全绿），klode-kit 不早于提交 `dbd4393`（含 WI-33a–d 修复）。
- 你有一个私有数据项目（下文 `<数据项目>`），里面有真实单据：图片（png / jpg）或 PDF。
- **数据项目没有备份、不在 git 里，也照样可以做**：本章只在一个新建的隔离子目录里工作，原件只复制、不移动、不改名。

## 数据与隐私红线

1. **只开本地路线**：`--routes vision,mlx`。云端两路（claude、codex）收的是打码后的图，但仍然是外发。外不外发由数据主人单独决定，不在本章默认范围内。
2. **原件只复制**：`cp -p` 到隔离目录的 `_inbox/`，不要 `mv`，也不要在原目录里运行任何命令。
3. **结果不进公开仓库，也不进 issue**。向本仓库反馈时只给计数、原因代码、命令输出里的英文状态行，以及版式描述（例如「两张截图左右拼接，2266×2248」）。不贴图，不贴记录正文，也不贴字段值、姓名、证件号、医院名。
4. **发布（G3）由数据主人亲手执行**。它会写数据项目的 `.mcp.json`，以及 `~/.klode/registry.toml` 这类真实登记。

## 步骤

### 8.1 建隔离目录，复制单据

```sh
export KK=<klode-kit 目录>
export DP=<数据项目>
export PJ="$DP/_klode-pilot"          # 隔离目录，整个可以移进 _trash/ 丢弃
mkdir -p "$PJ/_inbox"
printf '%s\n' _work/ _raw/ _masked/ _mask_review/ _private/ work/ > "$PJ/.gitignore"
# 按就诊/采样日期分批：一个日期一个收件箱目录，目录名就是确认页别名
mkdir -p "$PJ/_inbox/20261004" "$PJ/_inbox/20261010"
cp -p <原件目录>/报告A.pdf "$PJ/_inbox/20261004/"
cp -p <原件目录>/截图B.png "$PJ/_inbox/20261010/"
```

建议第一批只放 **1 页**，跑通了再放其余批次。

### 8.2 第一段：登记、OCR、审计（每个收件箱一次）

```sh
cd "$KK"
bin/klode-kit med-intake --project "$PJ" --inbox "$PJ/_inbox/20261010" --type lab --routes vision,mlx
echo "exit $?"
```

- 化验单用 `--type lab`，处方用 `--type rx`。
- `--routes vision,mlx`：只跑本地两路。这样 doctor 不要求工作区信任（WI-33b），不必先做第 7 章。

### 8.3 看确认页、点选

退出码 10 时，用浏览器打开**文件夹入口**：

```sh
open "$PJ/confirm/20261010/confirm.html"
```

每条分歧选一路的值，或选「都不对 / 手输」，或标「不是字段」。点完导出 `choices.json`。tesseract 的读数只作参照，选不了。

### 8.4 第二段：写回

```sh
bin/klode-kit pipeline --project "$PJ" --batch "$PJ/_inbox/20261010" \
  --type lab --routes vision,mlx --stage writeback --choices <导出的 choices.json>
```

- `--type` 和 `--routes` **都要与第一段一样再写一遍**。少了 `--routes`，doctor 会按「可能用云端」处理，去要求工作区信任，结果停在 preflight，exit 40。
- 第一段 exit 0（`nothing_to_confirm`）的批次，第二段**不带** `--choices`。

### 8.5 带文字层的 PDF

门户导出的 PDF 大多带文字层。第一段会显示：

```
ocr: 13 页文字层，跳过 OCR
```

这时文字层本身就是一路精确读数（`pdftext`），审计照常进行。各字段都一致的页会自动核对通过（`verified_by: auto`），然后照 8.4 不带 `--choices` 写回即可。

### 8.6 抽查记录

```sh
ls "$PJ/verified"
```

每批至少挑 1 份 `verified/<日期>-lab*.md`，和原件逐项对照：项目名、结果、单位、参考范围。PDF 可以用 `pdftotext -layout <原件> -` 看原文。

### 8.7（可选）建库、检查、发布

记录都核对过以后，按第 4、6 章的步骤走 `/klode-kit:kb-build`、`/klode-kit:kb-check`；数据项目换成 `$PJ`。发布（`kb-publish`）属 G3，由数据主人亲手执行。发布前先读第 6 章。

## 应该看到什么

维护者试点的实测（修复之后，只开本地两路）：

| 批次形态 | 第一段输出 | 确认页分歧 |
|---|---|---|
| 带文字层的 PDF，13 页 | `ocr: 13 页文字层，跳过 OCR`；`status: nothing_to_confirm` | 0。审计 13 页全部 `verified`，写回后得到 13 份记录 |
| 带文字层的 PDF，7 页 | 同上 | 0。得到 7 份记录 |
| 单张门户截图（两张左右拼接） | `ocr: 1 页 × 2 路 OK`；`audit: 13 条分歧 → confirm/<别名>.html` | 13（修复前 85） |
| 多张门户截图 / 长拼接图 | `awaiting_confirm` | 待核：WI-33e（tesseract 作几何参照）完成后重测。修复前 3 页就有 267 条，几乎每个字段都要点 |

抽查结果：PDF 批自动核对通过的记录，项目、结果、单位、参考范围与原文逐项一致。

## 通过判据

- 每个批次都有明确结局：`awaiting_confirm`（有确认页）、`nothing_to_confirm` 且写回后**有记录**，或者带修复提示的非 0 退出码。
- **没有「报成功、却 0 条记录」的批次。** 遇到这种情况就是缺陷，WI-33d 之后应当是 exit 20。
- 抽查的记录与原件一致。
- 确认页上的分歧数是你愿意点完的量。不是的话，报告里写下分歧数和下面「原因代码」的计数，这正是我们要的数据。

数原因代码的方法：

```sh
python3 - "$PJ" <<'EOF'
import json, sys, glob, collections
for a in sorted(glob.glob(sys.argv[1] + "/work/*/audit/a*")):
    c = collections.Counter()
    for l in open(a + "/candidates.jsonl"):
        c.update(x.get("reason") for x in json.loads(l)["uncertain"])
    print(a.split("/work/")[1], dict(c))
EOF
```

这段只打印批次号、修订号和原因计数，不会打印任何字段值。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| preflight exit 40，`MISSING project_trust` | 用到了云端路线，或者第二段没写 `--routes`。数据项目的上级目录已被信任时，开 `claude` 也**不会弹**信任框 | 只开本地路线，并且两段都写 `--routes vision,mlx`。确实要用云端路线时，按 doctor 给出的修法做（`git init` 后开 `claude` 接受信任，或者由你本人在 `~/.claude.json` 里给该目录加信任，属 G3） |
| 一整页文字被识别成竖排，分歧很多，MLX 输出同一行反复出现 | 旧版本方向检测把正着的页转了 90° 或 270° | 升级到 `2b97020` 之后（方向检测改用 tesseract OSD）。排查方法：`work/<批次>/derived.jsonl` 的 `transform.rotate` 应当是 0 |
| PDF 批报「无需确认」，但 `records/` 下没有这一天 | 旧版本对文字层 PDF 不做审计 | 升级到 `dbd4393` 之后 |
| 输出写「26 处失败（mlx:p001…）」，其实是文字层 | 旧版本把「跳过」算成了「失败」 | 同上 |
| 截图批几乎每个字段都要点，原因代码以 `no_geometry` / `no_bbox_crop` 为主 | 只有 Vision 的估算框，缺精确几何 | WI-33e 修复中，待核 |
| MLX 第一次运行很慢 | 加载约 3.9 GB 权重 | 正常现象，之后会快 |

## 费用

只开本地两路：0。不调用任何模型 API。本机 CPU/GPU 实测：1 页截图约 15 秒，6 页约 45 秒，20 页文字层 PDF 约 10 秒。

## 隐私与报告方式

在 [bubiji/klode-kit](https://github.com/bubiji/klode-kit/issues) 开 issue，标题以 `[T08]` 开头。只写这些：

- klode-kit 提交号、macOS 版本。
- 每批的形态描述（截图 / 拼接图 / 文字层 PDF / 扫描 PDF，页数，像素尺寸）。
- 第一段和第二段输出里的状态行（`ocr:`、`audit:`、`status:`）、退出码，以及上面那段脚本打印的原因计数。
- 抽查结论：一致，或者「第 N 行的单位不一致」这种**不含数值**的描述。

不要附图、记录文件、`work/` 目录，也不要写任何字段值。
