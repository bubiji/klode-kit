# T06 G3 发布登记

层：2 合成数据亲手验　闸门：G3（登记到 MCP / 注册表）、G5（信任）　时间：20–30 分钟　花费：0（不调用模型）

## 目的

发布（`kb-publish`）是整条流水线里**唯一会写你机器上持久配置的一步**：它原子地切换 `kb/<库>/current`，并做四件外部登记——写数据项目的 `.mcp.json`、写 `.claude/settings.local.json` 批准该 MCP、把专家 agent 文件放进 `.claude/agents/`、更新 klode 注册表。自动化测试一律把 `HOME` 和注册表指向临时目录，**从未碰过真实路径**。这一项让你亲手确认：

1. 发布、回滚、重放、清理这几条路径都按文档工作；
2. 未检查的构建发布不了；
3. 某个登记失败时，其余登记不受牵连，修好后能补做；
4. 整个过程**没有碰你真实的 `~/.klode/registry.toml`**。

## 前提

- 已做完 T04 的 4.1–4.3：你有演示项目 `<演示目录>/rxdemo`，里面已有一个检查通过并发布过的构建，`$DEMO/registry/registry.toml` 存在。
- 本章所有命令都在 `rxdemo` 目录里运行，并且 `KLODE_REGISTRY` 必须已设置：

```sh
export KK=<klode-kit 目录>
export DEMO=<演示目录>
export KLODE_REGISTRY="$DEMO/registry/registry.toml"
cd "$DEMO/rxdemo"
```

**对真实数据项目发布，不属于本章**，见第 8 章；真实项目必须由你本人决定并亲手执行。

## 步骤

### 6.0 记下真实注册表的状态（只读）

```sh
ls -l ~/.klode/registry.toml
```

记下修改时间（若该文件不存在也记下「不存在」）。本章结束时再看一次，必须一模一样。

### 6.1 看发布日志

```sh
cat kb/rxdemo/PUBLISH.log
```

应该看到：每行一个 JSON，字段 `seq`（从 1 递增）、`action`、`status`、`by`（形如 `klode-kit/0.1.0.dev0`）、`at`、`target_build_id`。T04 发布后应有 5 行，`action` 依次为 `switch`、`mcp_json`、`registry`、`agent`、`approve`，`status` 都是 `done`。

### 6.2 建第二个构建并发布（切换）

```sh
"$KK/bin/klode-kit" build --project . > /dev/null
export B1=$(ls kb/rxdemo/builds | grep '^b-' | head -1)
export B2=$(ls kb/rxdemo/builds | grep '^b-' | tail -1)
echo "$B1 $B2"
"$KK/bin/klode-kit" kb-check --kb kb/rxdemo --build "$B2" --entry manual > /dev/null; echo "check=$?"
"$KK/bin/klode-kit" kb-publish --kb kb/rxdemo --project . --build "$B2"
ls -l kb/rxdemo/current
```

`build` 要等一会儿（卡片和书桌由程序生成，不调模型）。两个构建号只差时间戳（同一秒内连续构建可能让构建号相近，`ls` 的顺序就是先后）。应该看到：

- `check=0`；
- 五行 `kb-publish: done ...`，其中最后一行是 `approve  rxdemo-klode already enabled`（已经批准过，不重复写）；
- `current` 现在指向 `builds/<B2>`。

### 6.3 未检查的构建发布不了

```sh
"$KK/bin/klode-kit" build --project . > /dev/null
export B3=$(ls kb/rxdemo/builds | grep '^b-' | tail -1)
"$KK/bin/klode-kit" kb-publish --kb kb/rxdemo --project . --build "$B3"
echo $?
ls -l kb/rxdemo/current
```

应该看到：

```
kb-publish: refused: check_receipt.json: missing or unreadable (the build was not checked)
```

加一行 JSON（`"exit_code": 30`、`"reason": "contract_violation"`）；退出码 30；`current` **仍指向 B2**，没有被动。

### 6.4 回滚

```sh
"$KK/bin/klode-kit" kb-publish --kb kb/rxdemo --project . --rollback-to "$B1"
ls -l kb/rxdemo/current
```

应该看到：

```
kb-publish: done          rollback
kb-publish: done          mcp_json  rxdemo-klode -> build <B1>
kb-publish: done          registry  rxdemo -> build <B1>
kb-publish: done          agent  rxdemo-klode-expert.md
kb-publish: done          approve  rxdemo-klode already enabled
```

`current` 指回 B1，`.mcp.json` 里 `env.KLODE_KIT_BUILD` 变回 B1（`grep KLODE_KIT_BUILD .mcp.json`）。

### 6.5 一项登记失败，其余照常；修好后重放

先备份 `.mcp.json`，再把它弄坏：

```sh
cp .mcp.json "$DEMO/mcp.good.json"
printf '{not json' > .mcp.json
"$KK/bin/klode-kit" kb-publish --kb kb/rxdemo --project . --build "$B2"
echo $?
cat .mcp.json
```

应该看到：

```
kb-publish: done          switch
kb-publish: failed        mcp_json  .mcp.json cannot be read as JSON (Expecting property name enclosed in double quotes: line 1 column 2 (char 1)); left as it is
kb-publish: done          registry  rxdemo -> build <B2>
kb-publish: done          agent  rxdemo-klode-expert.md
kb-publish: done          approve  rxdemo-klode already enabled
```

退出码 **21**（发布后登记有失败）。注意三点：`switch` 已完成（`current` 切到了 B2）；只有 `mcp_json` 失败，其余三项照做；`.mcp.json` 的内容**逐字节保持你弄坏后的样子** `{not json`，没有被覆盖。

现在修好文件并重放：

```sh
cp "$DEMO/mcp.good.json" .mcp.json
"$KK/bin/klode-kit" kb-publish --kb kb/rxdemo --project . --replay "$B2"
echo $?
```

应该看到 `kb-publish: done          mcp_json  rxdemo-klode -> build <B2>`，一行 JSON（`"mode": "replay"`，`actions` 里只有这一项），退出码 0。对一个没有未完成登记的构建再重放，`actions` 是空的 `[]`。

### 6.6 单独重做四项登记

```sh
"$KK/bin/klode-kit" register --kb kb/rxdemo --build "$B2" --project .
```

应该看到一行 JSON：`"schema": "klode-kit.register/1"`、`"exit_code": 0`、`"reason": "ok"`，`actions` 四项（`mcp_json`、`registry`、`agent`、`approve`）都是 `done`。它是幂等的（再跑一次结果相同）。

### 6.7 清理旧构建（移动，不删除）

先再建一个构建 B4，让没发布过的 B3 不再是「最新的」：

```sh
"$KK/bin/klode-kit" build --project . > /dev/null
"$KK/bin/klode-kit" kb-publish --kb kb/rxdemo --project . --prune --keep 1
ls kb/rxdemo/builds kb/rxdemo/builds/_trash
```

应该看到一行 JSON：`"mode": "prune"`，`"moved"` 是 `[B3]`（没发布过、也不是最新的那个），`"protected"` 说明哪些被保留及原因：`current`（当前发布的 B2）、`rollback_target`（上一次发布的 B1，留作回滚目标）、`recent`（最新的 1 个，即 B4）。被移走的构建出现在 `kb/rxdemo/builds/_trash/` 下，**没有任何东西被删除**。

### 6.8 检查登记内容

```sh
cat .mcp.json
cat .claude/settings.local.json
ls .claude/agents
cat "$DEMO/registry/registry.toml"
```

应该看到：

- `.mcp.json`：只有 `rxdemo-klode` 一项；`command` 是启动器的绝对路径，`args` 是 `["mcp", "--kb", "<演示项目里的 kb 绝对路径>"]`，`env.KLODE_KIT_BUILD` 是当前构建号。
- `settings.local.json`：`enabledMcpjsonServers` 含 `rxdemo-klode`。
- `.claude/agents/rxdemo-klode-expert.md`：第一段 frontmatter 之后有一行 `<!-- klode-kit build <构建号> -->`（构建标记）。
- 注册表：一个 `[[kb]]`，`id = "rxdemo"`，`path` 指向 `.../kb/rxdemo/current/library.toml` 的位置（形如 `<绝对路径>`），`build_id` 是当前构建。

### 6.9 确认没碰真实注册表

```sh
ls -l ~/.klode/registry.toml
```

必须和 6.0 记下的一致。若不一致，**立即停止并报告**（这是最严重的一类发现）。同时确认没有设置 `KLODE_REGISTRY` 时的默认位置是 `~/.klode/registry.toml`——那正是你不应该在本章里写到的位置，所以第一步要设置变量。

## 通过判据

- [ ] 6.2 切换成功，`current` 指向新构建。
- [ ] 6.3 未检查的构建退出码 30，`current` 不变。
- [ ] 6.4 回滚成功，`.mcp.json` 的 `KLODE_KIT_BUILD` 随之变回。
- [ ] 6.5 退出码 21，仅 `mcp_json` 失败，坏文件逐字节保留；重放后补做成功。
- [ ] 6.7 被清理的构建在 `_trash/` 里，没有删除。
- [ ] 6.9 `~/.klode/registry.toml` 的修改时间前后一致。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 提示找不到 `rxdemo` 或 `kb/rxdemo` | T04 没做完。回到 T04 的 4.1–4.3。 |
| 6.3 里 `kb-publish` 居然成功了 | 你的 B3 之前被检查过，或 `B3` 变量取到了 B2。`echo "$B2 $B3"` 确认不同；这种情况若 `check_receipt` 不存在却仍发布成功，是 bug，请报告。 |
| 6.7 `moved` 是空的 | 构建数量不超过保留数，或都被 `protected`。这不是错误。 |
| 发布后 `claude` 里看不到专家或 MCP | 回第 7 章确认信任；新写的 agent 要新开会话才生效。 |
| 同时开了两个终端发布 | 项目有锁，另一个会等待或以退出码 40 报告构建锁；一次只发布一个。 |

## 费用与隐私

- 0 美元。全程只写演示项目和 `$DEMO/registry/`，不写 `~/.claude`、`~/.claude.json`、`~/.klode`。
- 结束后 `unset KLODE_REGISTRY`，把 `$DEMO/rxdemo`、`$DEMO/registry` 整个移走（不要删）。
- `.mcp.json`、`registry.toml`、`PUBLISH.log` 里有本机绝对路径，贴到报告前换成占位符。
