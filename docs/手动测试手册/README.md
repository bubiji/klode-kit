# klode-kit 手动测试手册

这本手册写给**愿意帮忙测试的开源用户**。自动化测试能做的都已经做完（见仓库 `README.md` 第 6、7 节）；剩下的是机器做不了的事：要人在浏览器里点、要用你自己的 Claude Code 账号提问、要在你的机器上装一遍、要花真钱调云端模型，以及用真实数据跑一次。每一项都写成了照着做就行的步骤，并写明「应该看到什么」「怎么算通过」。

## 先看这三条红线

1. **不要拿真实个人数据来测**（病历、化验单、处方、身份证件……）。第 1–7 章全部只用本仓库自带的合成样本（`tests/fixtures/` 里的假名「测试患者甲」、假编号 `T-0000001`、假药「示例片」）。第 8 章（真实数据试点）只由数据的主人本人在自己的私有项目里做，**结果不要贴到公开的 issue 里**。
2. **不要写你的真实全局目录**：不要改 `~/.claude`、`~/.claude.json`、`~/.klode`。涉及发布登记的章节都用「私有注册表」（环境变量 `KLODE_REGISTRY` 指向一个临时文件），不会碰你真实的 klode 注册表。
3. **花钱的测试要你自己点头**：真实云端调用默认关闭（闸门 G2）。只有第 5 章会花钱，而且需要你亲手设置两个环境变量；脚本绝不会替你设置。

## 测试分层

| 层 | 名称 | 含义 |
|---|---|---|
| 1 | 机器层 | 命令自己判定通过与否（退出码、回执）。你的价值是「换一台机器、换一个系统版本再跑一遍」。 |
| 2 | 合成数据亲手验 | 输入是仓库自带的合成样本，但**要人看、人点、人判断**（确认页、专家问答、发布登记）。 |
| 3 | 真实数据试点 | 真实数据，只在数据主人自己的私有项目里做。 |

## 闸门（来自 TDD 计划「手动闸门」一节）

| 闸门 | 触发动作 | 手册里怎么处理 |
|---|---|---|
| G1 | 写 `~/.claude`（回修用户 skill、`claude plugin install` 用户级、写 `~/.claude/settings*.json`） | 本手册所有步骤都用 `claude --plugin-dir <klode-kit 目录>`，**不安装插件**，不碰 G1。 |
| G2 | 真实云端外发 / 真实模型调用（第一次带 `KLODE_KIT_REAL=1` 运行、四路最难页、隔离探针、宿主验收……） | 只有第 5 章。需要你自己设置 `KLODE_KIT_REAL=1` 和 `KLODE_KIT_GATE_ACK=G2-<yyyymmdd>`。只允许 `tests/fixtures/MANIFEST.json` 里登记过的合成图。 |
| G3 | 登记到用户或真实数据项目的 MCP（写 `.mcp.json`、`.claude/settings.local.json`、真实 `~/.klode/registry.toml`、`~/.claude.json`） | 第 4、6 章只对**合成的演示项目**发布，并用私有注册表。对真实项目发布属第 8 章。 |
| G4 | 安装依赖 / 下载权重（`pip`/`uv`、`brew install`、约 3.9 GB 的 MLX 权重） | 第 1 章。`doctor` 只报缺什么，**从不下载**；要不要装由你决定。 |
| G5 | 宿主信任：在目录里交互运行一次 `claude` 并接受工作区信任 | 第 7 章，第 3、4、6 章依赖它。 |

## 共用约定

整本手册用到这些占位符，请先换成你自己的值：

| 占位符 | 含义 |
|---|---|
| `<klode-kit 目录>` | 你 clone 下来的本仓库目录。 |
| `<演示目录>` | 你新建的一个空目录，专门放演示用的合成项目，用完可以整个移走。**不要**用你的真实数据目录。 |
| `<日期>` | 当天日期，`yyyymmdd`，例如 `20261031`（只在 G2 确认变量里用）。 |

所有命令里的 `bin/klode-kit` 指 `<klode-kit 目录>/bin/klode-kit`。写成路径变量更省事：

```sh
export KK=<klode-kit 目录>
export DEMO=<演示目录>
```

之后文中的 `"$KK/bin/klode-kit"` 就是启动器。命令输出里的路径会因机器而异，**报告问题前请把家目录路径换成 `~`**。

「待核」二字表示：这句输出文字是从源码或测试里读到的，写手册时没有在真实环境里亲眼验证，请你按实际情况为准，并在报告里告诉我们是否一致。

## 如何报告结果

每做完一项（无论通过与否）都请报告。**通过也要报**，我们要知道有多少种环境验证过了。

**去哪里报：** 在 <https://github.com/bubiji/klode-kit/issues> 新开一个 issue（标题格式 `[手动测试 T03] 通过 / 失败：一句话`）。命令行也可以：

```sh
gh issue create -R bubiji/klode-kit --title "[手动测试 T03] 通过：macOS 15 / Apple M2" --body-file <你写好的报告文件>
```

**报告模板**（复制下面整段，填空）：

````markdown
## 测试编号与结果
- 测试编号：T0x（章节名）
- 结果：通过 / 部分通过 / 失败 / 未做完（卡在第几步）

## 环境
- 系统与芯片：（`sw_vers` 与 `uname -m` 的输出）
- klode-kit 版本：（`<klode-kit 目录>/bin/klode-kit --version` 的输出）
- 代码版本：（在 klode-kit 目录里运行 `git rev-parse --short HEAD`）
- Claude Code 版本：（`claude --version`）；如用到 Codex：（`codex --version`）
- Python / uv：（`python3 --version`、`uv --version`）
- 本机引擎：`doctor` 里 ocrmac / mlx 是否通过；是否用了回放（`KLODE_KIT_ENGINE_REPLAY`）

## 做了哪些步骤
（按章节里的步骤编号写：「1–5 做了，第 6 步没做」。偏离手册的地方请写出来。）

## 预期 vs 实际
| 步骤 | 手册说应该看到 | 我实际看到 |
|---|---|---|
| 例：3.4 | `audit: 4 条分歧 → confirm/20261022.html` | （粘贴你的输出；没有差别就写「一致」） |

## 通过判据
（逐条列章节里的「通过判据」，每条写 通过 / 不通过 / 没测）

## 附件
（见下面的脱敏要求。没有就写「无」。）

## 其他
（任何觉得别扭的地方：措辞、等待时间、报错信息看不懂……）
````

**附件的脱敏要求（务必做）：**

1. 附件只能来自合成样本的测试。第 8 章的内容不要贴到公开 issue。
2. 把所有家目录路径换成 `~`，把你的用户名、机器名、邮箱、仓库私有地址删掉或换成占位符。检查命令：`grep -rn "/Users/\|/home/" <你要贴的文件>`，有输出就先替换。
3. 终端输出直接复制文字，不要截图（截图里容易带出路径和用户名）。必须截图时，先把窗口标题、路径栏裁掉。
4. 可以贴的：命令的退出码与输出、`work/<批次号>/receipt.json`、`work/lanes/<lane>.json`（先按第 2 条处理）。**不要贴**：`~/.claude.json`、任何含 token / 密钥的文件、`.mcp.json` 里带绝对路径的整段（换成占位符再贴）。
5. 你自己的真实文档、真实截图、真实 OCR 结果一概不要上传，哪怕你觉得「没什么敏感信息」。

提交前自检：在 klode-kit 目录里运行 `bin/klode-kit dev privacy-scan` 只扫描本仓库，不会扫你的附件，所以附件要自己看一遍。
