# T03 U8 确认页点选

层：2 合成数据亲手验　闸门：G5（数据项目要先接受工作区信任）　时间：20–30 分钟　花费：0（回放，不调用模型）

## 目的

这是 issue [#6](https://github.com/bubiji/klode-kit/issues/6) 里「用户亲手点」的一半。自动化已经覆盖了页面结构、导出器和写回；**没有人覆盖的是**：真浏览器里的单选按钮、手输框、下载按钮、分歧小图是否真的显示、小图和候选值对不对得上。本项就是让你在浏览器里把一份确认页从头点到尾，再把结果写回，检查记录的最终状态。

对应用户用例 U8：打开 `confirm/<别名>/confirm.html`，每条分歧选一路或「都不对 / 手输」，导出 `choices.json`，写回；点完的记录成为 `verified`，留「都不对」又没手输的记录是 `disputed`，且不进构建输入。

## 前提

- T01 通过（`bin/klode-kit doctor` 全绿）。
- 一个浏览器（Chrome、Safari、Firefox 均可；维护者在 Chrome 上看过）。
- 能在终端里交互运行 `claude`（只为接受工作区信任，**不会发起任何模型调用**；见第 7 章）。
- 本章用**回放**：OCR 四路的读数取自仓库里录好的合成样本（`tests/fixtures/fx-u8/engine`），所以结果每次一样。它验证的是「页面和写回」，不验证 OCR 质量。想看真实本机识别，见 3.3 的变体 B。

## 步骤

### 3.1 准备演示项目

```sh
export KK=<klode-kit 目录>
export DEMO=<演示目录>
mkdir -p "$DEMO/_inbox/2026-10-22" "$DEMO/data-demo"
cp "$KK"/tests/fixtures/fx-u8/images/*.png "$DEMO/_inbox/2026-10-22/"
cd "$DEMO/data-demo"
git init -q .
printf '%s\n' _work/ _raw/ _masked/ _mask_review/ _private/ work/ > .gitignore
ls ../_inbox/2026-10-22
```

应该看到：`p001.png` 和 `p002.png`（两张合成化验单图，抬头是假名）。

### 3.2 接受工作区信任（G5）

```sh
claude
```

在 `data-demo` 目录里启动后，出现信任对话框就接受，然后用 `/exit` 退出，**不要提问**。细节与出错处理见第 7 章。然后：

```sh
"$KK/bin/klode-kit" doctor --project .
echo $?
```

应该看到 `doctor: all <N> checks passed`，退出码 0（N 在项目模式下比机器模式多 4 项，具体数字待核）。如果只缺 `project_trust`，回到上一步；只缺 `project_gitignore`，照它的 `fix:` 行执行。

### 3.3 运行入库，停在待确认

**变体 A（推荐，回放，结果确定）：**

```sh
KLODE_KIT_TEST_SEAMS=1 \
KLODE_KIT_ENGINE_REPLAY="$KK/tests/fixtures/fx-u8/engine" \
"$KK/bin/klode-kit" med-intake --inbox ../_inbox/2026-10-22 --project .
echo $?
```

这两个环境变量是测试接缝：前者允许使用接缝，后者让四路 OCR 读取录制的读数而不是真的识别。它们只在这个命令里生效。

应该看到（标准输出的最后三行，退出码 **10**）：

```
ocr: 2 页 × 4 路 OK
audit: 4 条分歧 → confirm/20261022.html
status: awaiting_confirm
```

标准错误里还有这些行（顺序和细节可能略有差异）：

```
kb-ocr: masked pictures ready for the cloud routes: 2 page(s) in _masked/
kb-ocr: batch <12 位十六进制>: 2 page(s), routes vision,mlx,claude,codex, 0 issue(s); receipt work/<批次号>/receipt.json
kb-audit: batch <批次号>: audit revision a1 (new), 2 record(s), 2 awaiting confirmation
confirm page (with crops): confirm/20261022/confirm.html
```

退出码 10 是**正常停止**（等你确认），不是错误。批次号是 12 位十六进制，由图片内容决定。

这时目录里应有：`confirm/20261022/confirm.html`（要打开的页面）、`confirm/20261022.html`（只是找页面用的链接，**不要打开它**，小图会裂）、`work/<批次号>/`、`work/20261022`（日期别名）、`_masked/`、`_mask_review/`、`records/`、`verified/`。

**变体 B（可选，真跑本机两路）：** 去掉两个环境变量，改用 `--routes vision,mlx`，只用本机 Vision 和 MLX，**不会发往云端**：

```sh
"$KK/bin/klode-kit" med-intake --inbox ../_inbox/2026-10-22 --project . --routes vision,mlx
```

应该看到 `ocr: 2 页 × 2 路 OK` 和 `audit: <若干> 条分歧 → confirm/20261022.html`，退出码 10。分歧条数取决于你机器上的真实识别结果（维护者机器上是 6 条，你的可能不同）。需要 MLX 权重。**不要加 `claude` 或 `codex` 路**，那是第 5 章的花钱操作。变体 B 的候选只有两路，下面 3.5 的具体点选方案要自己调整。

### 3.4 打开页面并逐项检查

```sh
open confirm/20261022/confirm.html
```

（macOS 的 `open` 会用默认浏览器；也可以手动把这个文件拖进浏览器。）

**页面整体应该有：**

- 标题「klode-kit 确认页」，下面一行「批次 `<批次号>` · 审计修订 `<批次号>/a1`」。
- 摘要行：「2 条记录；待点选 4 处；缺路不可点选的记录 0 条」（变体 A）。
- 说明文字：「本页只在本机打开：分歧小图是本机裁图，不外发……推荐值（多数票）只是推荐。」
- 底部按钮「导出 choices.json」，旁边有一个状态文字区。

**每一条分歧应该有：**

1. 标题行：字段名（如 `wbc`）、字段号（如 `r006-number-0`）、判定标签（「多数」「全不同」或「平票」）。
2. 一张**分歧小图**（`alt` 为「分歧小图」）。必须真的显示出来，不是裂图图标；图里应是该行的单据文字。
3. 四个候选，顺序固定：`vision`、`mlx`、`claude`、`codex`，每个带数值。**没有 tesseract**（它只做版面几何，不投票）。
4. ★推荐标记：只出现在「多数」条目里持多数值的那几路上；「全不同」和「平票」条目**没有★**。
5. 三个固定选项：「都不对」、「不是字段（删除）」、「手输：」加一个文本框。

**变体 A 的四条应当是（本机识别无关，是录制的读数）：**

| 字段 | 判定 | vision | mlx | claude | codex | ★ |
|---|---|---|---|---|---|---|
| `wbc`（`r006-number-0`） | 多数 | 6.2 | 6.2 | 6.2 | 8.2 | vision、mlx、claude |
| `platelet`（`r008-number-0`） | 全不同 | 210 | 218 | 270 | 216 | 无 |
| `rbc`（`r007-number-0`） | 平票 | 4.61 | 4.61 | 4.67 | 4.67 | 无 |
| `neutrophil-pct`（`r009-number-0`） | 多数 | 70.7 | 70.1 | 70.1 | 70.1 | mlx、claude、codex |

**你要用眼睛判断的**（机器判断不了）：小图里该行的数字，是否和你认为「真值」相符？把你认为正确的值记下来。合成单据的真值在 `$KK/tests/fixtures/fx-u8/truth.json`（想先偷看再点也可以，但「看小图自己判断」才是这个测试想验证的体验）。

### 3.5 点选

按下表点选（变体 A）。这个方案刻意覆盖了四种情形：采纳推荐、手输、留「都不对」不手输、选非多数路之外的一路。

| 字段 | 操作 |
|---|---|
| `wbc` | 选 `vision`（★推荐的值） |
| `platelet` | 选「手输：」，在文本框填 `214` |
| `rbc` | 选「都不对」，**不要**手输 |
| `neutrophil-pct` | 选 `mlx`（★推荐的值） |

边点边看底部状态文字：每点一项，应更新为「已选 N / 4」（N 是已选条数；初始文案待核）。

然后点「导出 choices.json」。应该看到：

- 浏览器下载了一个 `choices.json`（默认在「下载」文件夹）。
- 状态文字变成「已导出 4 条（未点完的记录写回时会被拒绝）」。

如果提示「导出失败：……」，把这行原文记入报告。

小试验：**少点一条**再导出，状态文字仍会提示已导出 N 条，但写回时那条记录整条被拒绝（见 3.9）。

把下载的文件移到一个明确的位置，后面用 `<choices.json 路径>` 指它：

```sh
mv ~/Downloads/choices.json "$DEMO/choices.json"
```

### 3.6 写回

方式一，命令行（两种变体都适用，变体 A 要继续带两个环境变量，因为这条命令会按「三哈希」规则复用前面的阶段）：

```sh
KLODE_KIT_TEST_SEAMS=1 \
KLODE_KIT_ENGINE_REPLAY="$KK/tests/fixtures/fx-u8/engine" \
"$KK/bin/klode-kit" pipeline --batch ../_inbox/2026-10-22 \
  --choices "$DEMO/choices.json" --stage writeback --project .
echo $?
```

**必须带 `--stage writeback`**：`pipeline` 不带 `--stage` 时跑全部阶段，会一直跑到建库和发布。

应该看到（变体 A 且按 3.5 方案点选，退出码 **10**）：

```
kb-audit --writeback: r-<记录号>: r2 verified (<批次号>/a1/c0003)
kb-audit --writeback: r-<另一个记录号>: r2 disputed (<批次号>/a1/c0004)
pipeline: writeback: done (ran, exit 10)
```

末尾还有一行 JSON：`"exit_code": 10`、`"reason": "awaiting_confirm"`，`stages` 里 `preflight`、`ocr`、`audit` 是 `"how": "reused"`，`writeback` 是 `"how": "ran"`。退出码 10 在这里的含义是「还有记录在等人」（disputed 那条），不是失败。

方式二，在 Claude Code 里用 skill（要有模型额度，但只是调命令、不读图）：`claude --plugin-dir <klode-kit 目录>`，然后说「分歧我点完了，写回」，skill 会依次运行 `kb-audit --writeback <choices.json>`、`kb-audit --writeback`、`views`。本章以方式一为准。

### 3.7 检查记录的最终状态

```sh
ls records verified
grep -n '"status"\|"uncertain"\|"verified_by"' -A1 records/2026-10-22-lab.md records/2026-10-22-lab-2.md
grep -n 'r008-number-0' verified/2026-10-22-lab.md
```

应该看到：

- `verified/` 下**只有** `2026-10-22-lab.md`（第一页的记录）。
- `records/2026-10-22-lab.md`：`"status": "verified"`、`"uncertain": []`、`"verified_by": "human"`。
- `records/2026-10-22-lab-2.md`：`"status": "disputed"`，`"uncertain"` 列表里有 `p002-l07`（渲染成多行列表）。
- `verified/2026-10-22-lab.md` 里 `r008-number-0` 的值是 `"214"`（你手输的）。

这三点正对应 04 §6 的 U8：点完的记录 `status: verified`；留「都不对」未手输的是 `status: disputed`、`uncertain: [p002-l07]`。记录号（`r-` 开头）和批次号随输入而定，以你的输出为准。

**disputed 不进构建输入**：本章不建库，这一条由自动化覆盖（`build_receipt.json` 的输入清单里没有 disputed 记录）；如要亲眼看，做第 4 章并检查 `kb/<库名>/current/library/records/`，只有 verified 记录的 id。

### 3.8 重复提交不产生新修订

批次号用 `ls work` 看（12 位十六进制那个目录）：

```sh
ls work
"$KK/bin/klode-kit" kb-audit --batch <批次号> --writeback "$DEMO/choices.json" --project .
ls records/_rev
```

应该看到 `records/_rev/` 里每条记录仍只有 `r1`、`r2` 两个修订文件，没有 `r3`：同一份 choices 重复提交是幂等的。

### 3.9 整份拒绝（坏 choices）

```sh
echo '{"x":1}' > "$DEMO/bad.json"
"$KK/bin/klode-kit" kb-audit --batch <批次号> --writeback "$DEMO/bad.json" --project .
echo $?
```

应该看到：

```
kb-audit --writeback: .../bad.json is not klode-kit.choices/1: batch_id: 'batch_id' is a required property
```

以及一行 JSON 回执 `"exit_code": 30`、`"per_record": []`。退出码 30，**零写入**。同理，用旧页面导出的 choices、或点了 tesseract 的 choices，也会整份被拒（退出码 30）。

### 3.10 重开一个已 verified 的字段（可选）

```sh
"$KK/bin/klode-kit" kb-audit --reopen r-<记录号>/r006-number-0 --reason "手册演示" --project .
echo $?
```

字段号用 `grep r006 verified/2026-10-22-lab.md` 找到完整形式。应该看到：

```
kb-audit --reopen: r-<记录号>/r006-number-0: opened <批次号>/a1/o0001 (r2); confirm page work/<批次号>/audit/a1/reopen/o0001.html
```

退出码 10。打开这个只有一条的页面（`open work/<批次号>/audit/a1/reopen/o0001.html`；注意这个页面的小图路径与主页面不同，**小图是否显示请在报告里写明**，待核），选「手输」填 `6.5`，导出 `choices.json`，再按 3.6 写回。应该看到 `r3 verified`，`verified/2026-10-22-lab.md` 里该字段变成 `"6.5"`，旧修订 `r1`、`r2` 仍在 `records/_rev/`。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面里的小图是裂的 | 你打开的是 `confirm/20261022.html` 那个链接，小图用相对路径会找错目录。打开 `confirm/20261022/confirm.html`。（`kb-audit` skill 已知坑 A05、`med-intake` 已知坑 M02） |
| 写回退出码 30，什么都没写 | choices 与当前确认页对不上（批次、审计修订、封存码），或点了 tesseract、漏了待确认字段。不要手改 `choices.json`，用当前页面重新点选再导出（已知坑 A01）。 |
| 导出的 choices 里条数少于页面条数 | 你有没点的项。未点完的记录写回时整条被拒绝。 |
| 留了「都不对」又没手输，记录是 disputed | 设计如此（已知坑 A03），disputed 不进构建输入；想补就再点一次手输，或用 3.10 的 `--reopen`。 |
| 四路读成同一个错值，没出现在确认页 | 一致不等于正确（已知坑 A04）。发现后用 `--reopen`。 |
| `doctor` 一直报 `project_trust` | 去第 7 章。 |
| 浏览器没下载 `choices.json` | 浏览器可能拦了下载；允许后再点一次。页面不联网，用的是本地 blob 下载。 |
| 想重来一遍 | 把 `$DEMO/data-demo` 整个移走（移到 `_trash/` 类目录，不要删），回到 3.1。 |
