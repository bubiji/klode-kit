## 1. 根因与改法

为什么要做插件：用户要的是「扫描件/截图 → 可引用原文的 klode 库」且 `/kb-build` 书架+书桌**全自动**（交接§1 第 1、5 条）；现有两个用户 skill 只覆盖「有文字层的书 → 书架/书桌」，且 16 步靠人按表敲（实测§0 一句话结论）。

| 缺口 | 证据（文档+章节） | 本设计的改法 |
|---|---|---|
| 无编排层：16 步各自退出码，顺序靠人记 | 实测§4 G1、§1.1 SKILL.md 行 | `src/klode_kit/pipeline.py` 一条命令串 ①–⑬，每步写 receipt，失败即停并指明回路（§2、§4） |
| 三条回路（路由不足/引文非 FOUND/锚点失效）不自动 | 交接§2「三条回路」；实测 G2 | 回路写进 pipeline：verify 未达阈值→列未命中题回书桌；NOT FOUND→定位卡重派 writer（≤N 次）；citation-rot→自动 `fix_anchors` 再复检 |
| 门禁 1 不强制、门禁 2 放过 stub 卡与折叠标点 | 实测 B2、B6、G3、G4；实测§2 步骤 12、13b | `write_card` 内置 `check_cards`，FAIL 不写；`/kb-check` 加全库判据（zoom 全 full、aliases≥10、锚点≥N） |
| 只支持有文字层的源；章头正则只认英文 | 实测 G6、§2 步骤 3b；E01/E02 | `/kb-ocr` 四路读图 → JSONL → 审计 → txt 进本流程；`HEAD_RE` 外置配置（中文「第 N 章」「一、」「检验报告」） |
| 无脱敏、无 PII 处理 | 实测 G7；交接§2「抬头打码」；OCR§4 003 架构「正文永不出网」 | 两处机制：外发前**抬头打码**（N5）；导出 txt 前**脱敏器**（姓名/编号/日期偏移）+ 回归测试（§6） |
| 医疗「verified 结构化记录 → txt / L1」不存在 | 实测 G8；交接§2 医疗层 | `records_to_txt.py` / `records_to_l1.py` 确定性生成 + 校验（三元组逐字可 grep）（§3 末） |
| 四路比对、字段抽取、确认页、写回门禁全是零 | OCR§0 第 4 条、§6.2、§7 N1–N9 | 搬 189 的 `diff_page / vote / apply_fixes 规则 / quote_crop.find_block / cer`，新写 N1–N9（§2 目录树） |
| 两个 skill 共 13 脚本 0 测试；硬编码本机路径 | 实测 G9、G10、§1.2 agent 白名单绝对路径 | 插件内 `tests/` 四个 lane（§7）；`shutil.which("klode")` + 环境变量；registry 走 `klode --registry`（本机实跑确认该全局参数存在） |
| 登记 MCP 直接 user 级 `claude mcp add`，隐私库无机器强制 | 实测 G13、G7；交接§2「MCP 登记」 | 隐私库只登记到**数据项目**的 `.mcp.json`（project 级）；插件不登记任何具体库（§2 MCP 行、§8 冲突 5） |
| klode 发现不了表格数值互换，确认必须在导出前 | 交接§5 klode 行；E03/E04；E45 | 工作流固定顺序 ocr → audit（人工点选）→ build；verified 只来自确认页，不来自 `klode check`（§4） |

## 2. 架构

### 2.1 各层放什么

| 层 | 放什么 | 位置 | 出处 |
|---|---|---|---|
| plugin | 清单 `.claude-plugin/plugin.json`；插件根 = 本仓根 | `/.claude-plugin/plugin.json` | docs:skills「Skill folder as a plugin：加 `.claude-plugin/plugin.json` 即可捆绑 agents、hooks、MCP servers」 |
| skill（五个命令） | `/kb-ocr` `/kb-audit` `/kb-build` `/kb-check` `/med-intake`，各一个 `SKILL.md`，正文只做「解析参数 → 调 `src/` 脚本 → 读 receipt → 汇报」 | `skills/<name>/SKILL.md` | docs:skills「`commands/` 是旧格式仍可用……新工作优先用 skill」；实测 A11 已知坑并入各 SKILL.md |
| agent | `klode-card-writer`（便宜模型写卡，一卡一派）、`kb-verifier`（只读，对照原件判 verified/disputed）、`<kb>-expert` 由 `gen_agent.py` 生成到**数据项目** `.claude/agents/` | `agents/*.md`；expert 不进插件 | 实测 A10、A6；交接§2「agent 两个」；docs:sub-agents「插件 subagent 的 `hooks/mcpServers/permissionMode` frontmatter 被忽略」→ expert 需要 MCP 时必须落在项目侧 |
| MCP | 插件**不**自带 `.mcp.json` 里的具体库；`/kb-build` 末步把 `klode-mcp -c <toml>` 写入数据项目 `.mcp.json`；冒烟用 `smoke_mcp.py` 直连不依赖登记 | 数据项目 `.mcp.json` | 实测 A5「不登记也能跑」、G13；交接§2 |
| workflow | `kb-pipeline`：ocr → audit（确认页停）→ build → check 的 JS 脚本，运行名 `/klode-kit:kb-pipeline`，入参走 `args` | `workflows/kb-pipeline.js` | docs:workflows「Distribute a workflow in a plugin：放插件根 `workflows/`，按插件名命名空间」「Pass input to a saved workflow：全局 `args`」 |
| 脚本 | 全部实现代码在 `src/klode_kit/`，skill/agent/workflow 只调用；189 搬入的函数层与用户 skill vendoring 的脚本都在此 | `src/` | 用户全局规则「实现代码放 src/」；实测§6.1；OCR§2 判定列 |
| hooks | 可选：`PreToolUse` 拦 `Bash(codex exec -i *)` 时检查图片是否在 `_masked/` 或 `tests/fixtures/` | `hooks/hooks.json` | 交接§6「外发给 Codex 的图必须是合成样本或已打码图」；docs:hooks「`${CLAUDE_PLUGIN_ROOT}` 在 command/args 中替换」 |

插件组件目录的**精确名单**（`skills/ agents/ hooks/ workflows/ .mcp.json` 之外是否还有 `commands/` 等）：本地镜像无 plugin 组件参考页（docs:sub-agents 提到「plugin components reference」但镜像未收录；changelog 只证实 `.mcp.json`、`commands/`、`${CLAUDE_PLUGIN_ROOT}` 三者存在）→ **待核实 ①**。`${CLAUDE_PLUGIN_ROOT}` 是否在 SKILL.md 正文与 agent `allowed-tools` 里也替换（实测§6.1 的白名单写法依赖此点）→ **待核实 ②**。

## 4. Workflow 工作项

Workflow 为 JS 脚本，后台运行、`/workflows` 里 `p` 暂停/恢复、`s` 保存为命令；重启时已完成 agent 返回缓存结果（docs:workflows「Watch the run」「Resume after a pause」）。文档里**没有**「脚本阻塞等人工点选」的原语 → **待核实 ③**。因此确认页停点设计为「两段式」：第一段到生成确认页即结束并写 `awaiting_confirm`；用户点选后第二次调用 `/klode-kit:kb-pipeline` 传 `args={resume:<batch>}`，脚本检测 `choices.json` 存在才进入 build。

| 工作项 | 输入 | 输出 | 暂停点/闸门 | 失败回路 |
|---|---|---|---|---|

### D. 字段对应（4.1）——覆盖 §2.2 `compare.py`、§5 字段比对行

| 概念 | 定义 |
|---|---|
| 几何基准路 | 有 bbox 的本机路（默认 vision；E13 CER 最优）：行 = 其行框按 y 排序、竖直重叠 ≥50% 合并；列 = 行内字段 `x0` 按间距阈值聚类得 `col_id` |
| 无 bbox 路对齐 | claude/codex 行序列与基准行做单调对齐（`difflib`，行相似度 ≥ `line_sim_tau`，默认 0.6）；对不上的行 → 该路该行 `unaligned`；一行相似度对基准两行拼接更高 → `merged_rows` |
| 单元格 | `cell = (row_id, col_id\|ordinal, kind)`；`item_label` = 该行最左非数值 token（经 items.yaml 归一）；重复值保留 `ordinal` 与计数，比对按 cell 不按集合 |
| 票型 | 每 cell `{value: [engines]}`；全路齐且一致 → `agree`；多数 → 推荐值；平票/全不同 → 确认页。推荐值永远只是推荐 |
| 显式 uncertain | `missing_cell:<engine>`（该路该行少格）、`unaligned:<engine>`、`merged_rows:<engine>`、`swap_suspect`（少数路的两值恰为相邻行互换）——均进 r2.3 原因表 |
| 契约样例（`tests/contract/fields/`） | ① 重复数字：两行同为 `10` → 两个 cell 各自 4/4 agree，不合并；② 列错位：某路把数值落到单位列 → 该 cell 分歧并带 `item_label`；③ 两行互换：某路第 3/4 行数值对调 → 两个 cell 均分歧且 `swap_suspect`，**不得**判 agree；④ 缺行：某路少第 5 行 → 该行全部 cell `missing_cell`，三路一致也只能进确认页（04 U3「无分歧」以全路齐为前提，不变） |
