# 目录结构

klode-kit 是一个 Claude Code 插件：仓库根就是插件根（`.claude-plugin/plugin.json`）。本文说明仓库里每个目录和关键文件做什么，以及运行时在**数据项目**里产生的目录。

两个地方要分清：

- **本仓库**（插件）：代码、skill、agent、workflow、测试、合成样本。公开，不含任何真实数据。
- **数据项目**（使用者自己的目录，可以是私有仓库）：收件箱、OCR 结果、记录、知识库、确认页。插件只在它的当前目录或 `--project DIR` 里读写。本文第 4 节列出这些运行期目录。

## 1. 仓库顶层

| 路径 | 用途 |
|---|---|
| `.claude-plugin/` | 插件清单 `plugin.json`（名字 `klode-kit`，决定命令前缀 `/klode-kit:`）。 |
| `skills/` | 五个 skill，每个一个子目录和一个 `SKILL.md`。只做「解析参数、调命令、读回执、汇报」，没有业务逻辑。 |
| `agents/` | 两个插件 agent，见 1.1。 |
| `workflows/` | Workflow 脚本 `kb-pipeline.js`（薄壳，只排阶段顺序）。 |
| `hooks/` | `hooks.json`：PreToolUse 钩子，拦截不合规的 `claude` / `codex` 外发命令。 |
| `bin/` | 启动器 `bin/klode-kit`（shell 脚本）。插件的 `bin/` 会进 Bash 的 PATH。 |
| `scripts/` | 安装脚本 `scripts/install.sh`。 |
| `src/` | 全部实现，Python 包 `src/klode_kit/`（第 3 节）。 |
| `tests/` | 测试与合成样本（第 5 节）。 |
| `docs/` | 文档（第 2 节）。 |
| `.claude/` | 本项目的开发期配置：`.claude/tdd-guardian/` 放测试计划、测试矩阵、偏离记录、lane 配置 `config.json`。使用插件不需要它。 |
| `.github/` | CI：`.github/workflows/ci.yml`（在 macOS 上跑 privacy-scan、unit、contract_replay 和覆盖率闸门）。 |
| `work/` | 本仓库自己的运行产物：lane 回执 `work/lanes/`、覆盖率 `work/coverage/`、变异测试 `work/mutation/` 与 `work/mutation.json`。已被 `.gitignore` 忽略。 |
| `_trash/` | 回收站：任何「清理」都是把东西移到这里，不删除。已被 `.gitignore` 忽略。 |
| `_staging/` | 暂存区：暂时不能放进 `tests/` 的新测试（例如长时间变异测试期间不许改动 `tests/`），事后移入对应目录。不属于发布内容。 |
| `.venv/` | 本仓库的 Python 环境，由 `scripts/install.sh` 建立。已被 `.gitignore` 忽略。 |

顶层关键文件：

| 文件 | 用途 |
|---|---|
| `pyproject.toml` | 依赖（`klode==0.5.0` 等）、extras（`core`、`ocr-mac`、`mlx`、`dev`）、pytest 标记（lane）、覆盖率配置。 |
| `uv.lock` | 锁文件；`scripts/install.sh` 用 `uv sync --locked` 按它安装。 |
| `RELEASE.sha256` | 发布 sha 的登记，由 `bin/klode-kit dev release-manifest` 写入和核对。 |
| `.privacy-allowlist` | 隐私扫描已审阅的误报清单。 |
| `.gitignore` | 忽略 `.venv/`、`work/`、`_trash/` 等。 |
| `README.md` | 项目说明（2026-10-27 由 README_v2 覆盖，旧版在 `_trash/readme-20261027/`）。 |

### 1.1 skill 与 agent

| 路径 | 用途 |
|---|---|
| `skills/kb-ocr/` | `/klode-kit:kb-ocr`：一批图或 PDF 四路 OCR。 |
| `skills/kb-audit/` | `/klode-kit:kb-audit`：对齐投票、确认页、写回、重开字段。 |
| `skills/kb-build/` | `/klode-kit:kb-build`：书或核对过的记录建成 klode 库；带「已知坑」表。 |
| `skills/kb-check/` | `/klode-kit:kb-check`：整库检查，打印检查回执。 |
| `skills/med-intake/` | `/klode-kit:med-intake`：当天截图入库（两段式）。 |
| `agents/klode-card-writer.md` | 便宜模型，一次只写一张卡片，不碰 git，不能强行写入。 |
| `agents/kb-verifier.md` | 只读，只出建议（给确认页参考），不改任何记录。 |
| `workflows/kb-pipeline.js` | 两段式流水线：第一段到待确认处结束，第二段 `writeback`、`build`、`check`，显式要求才 `publish`。 |

## 2. `docs/`

| 路径 | 用途 |
|---|---|
| `docs/目录结构.md` | 本文。 |
| `docs/install.md` | 安装：环境前提、`scripts/install.sh`、Workflow / 信任前提、Bash 权限规则模板、命令短名。 |
| `docs/med-intake.md` | `/med-intake` 命令的行为说明（退出码、日期别名、回执）。 |
| `docs/med-intake-backup.md` | 数据项目的备份方案（只有文档，插件不实现任何备份动作）。 |
| `docs/pipeline/` | 流水线各阶段的设计与评审记录（需求摘要、概要设计、基线实测、TDD 计划）。 |
| `docs/spikes/` | 真实宿主上的探测报告（OCR 四路对比、云端读取隔离等）。 |
| `docs/wua/` | 三张通用工作流图（场景、用例 U1–U8、流水线），`.wf.json` 源文件加渲染出的 `.svg`。 |

## 3. `src/klode_kit/`

入口是 `src/klode_kit/__main__.py`：`bin/klode-kit <命令>` 就是 `python -m klode_kit <命令>`，命令表是其中的 `COMMANDS`。

### 3.1 顶层模块

| 文件 | 用途 |
|---|---|
| `src/klode_kit/pipeline.py` | 流水线内核：preflight、ocr、audit、writeback、build、check、publish 七个阶段，每阶段一份回执，已完成且输入哈希相同的阶段不重跑。 |
| `src/klode_kit/med_intake.py` | `med-intake`：登记收件箱、跑到 audit、停在待确认，建日期别名与 `confirm/` 链接。 |
| `src/klode_kit/publish.py` | `kb-publish`：把 `kb/<id>/current` 切到已检查的构建，`PUBLISH.log`，回放、回滚、清理。 |
| `src/klode_kit/register.py` | `register`：发布后的四项登记（`.mcp.json`、registry、expert agent 文件、`settings.local.json`）。 |
| `src/klode_kit/registry_write.py` | 登记用的原子写与按 id 幂等的 registry 更新。 |
| `src/klode_kit/mcp_wrap.py` | `mcp`：单个库的 MCP 服务，每次调用都跟随 `current`，换构建不用重启。 |
| `src/klode_kit/mcp_render.py` | MCP 包装的第二级降级渲染（走 klode 命令行）。 |
| `src/klode_kit/u5_probe.py` | `u5-probe`：直连与宿主两种探针，确认 MCP 读到的是刚发布的那个构建。 |
| `src/klode_kit/kb_check.py` | 旧入口的兼容层，正式实现在 `src/klode_kit/check/kb_check.py`。 |
| `src/klode_kit/loops.py` | `build --loops` 的三个修复回路（线索词、写卡、锚点）。 |
| `src/klode_kit/bridge.py` | 把写卡任务派给 `claude -p`（真实调用在闸门 G2 之后）。 |
| `src/klode_kit/gate.py` | 真实模型调用的共用闸门（需要 `KLODE_KIT_REAL` 与 `KLODE_KIT_GATE_ACK`）。 |
| `src/klode_kit/agents_check.py` | `check-agents`：静态检查 `agents/*.md`。 |
| `src/klode_kit/hostenv.py` | 读取宿主状态（工作区信任、`claude mcp get`）。 |
| `src/klode_kit/receipts.py`、`src/klode_kit/seams.py` | 回执写入；测试缝与暂停点（正式运行中不生效）。 |
| `src/klode_kit/items.py`、`src/klode_kit/cer.py` | `items.yaml` 项目名表的读取；字错率（CER）度量。 |

### 3.2 子包

| 子包 | 用途 |
|---|---|
| `src/klode_kit/ocr/` | 四路 OCR：本机 Vision 与 MLX，云端 Claude 与 Codex（只发打码图）；PDF 文字层分流、转正、批次执行 `run_batch.py`、发送器 `send.py`、隔离检查与钩子 `isolation_guard.py`、`privacy_guard.py`。 |
| `src/klode_kit/audit/` | 审计：字段抽取、逐行对齐、票型比对、闸门、裁剪分歧小图、确认页、写回、重开字段、兼容视图、kb-verifier 建议。 |
| `src/klode_kit/build/` | 建库：初始化、导出记录为文本、书架（切章、写卡、两道门禁）、书桌（desk）、专家 agent 生成、冒烟、13 步构建 `run_build.py`、脱敏。 |
| `src/klode_kit/check/` | `doctor`（逐项真实检查先决条件）与整库检查 `kb_check.py`。 |
| `src/klode_kit/config/` | 默认配置 `defaults.toml`、项目名表、打码规则、各路开关等数据文件，以及配置加载。 |
| `src/klode_kit/contract/` | 契约：JSON schema 加载、各类标识的生成公式、来源链（provenance）校验器。 |
| `src/klode_kit/schemas/` | 回执与记录的 JSON schema（`record.json`、`choices.json`、`build_receipt.json` 等）。 |
| `src/klode_kit/prompts/` | 给模型的提示词模板（读图、写卡、书桌综合）。 |
| `src/klode_kit/templates/` | 生成专家 agent 用的模板。 |
| `src/klode_kit/data/` | 随包数据（klode 0.5.0 的工具清单快照）。 |
| `src/klode_kit/eval/` | 字段与 OCR 质量评估工具（金标对比）。 |
| `src/klode_kit/devtools/` | 开发与发布工具：`run_lane`、`coverage_gate`、`privacy_scan`、`release_manifest`、`release_check`、`mutation_gate`、`fixture_manifest`、pytest 插件。 |

## 4. 数据项目里的运行期目录

这些目录不在本仓库里，由命令在数据项目中创建。建议把 `work/`、`_raw/`、`_masked/`、`_mask_review/`、`_private/` 放进数据项目的 `.gitignore`（`bin/klode-kit doctor --project DIR` 会检查）。

| 路径 | 内容 |
|---|---|
| `_inbox/` | 收件箱：原始截图与拍照，按日期分目录，例如 `_inbox/2026-10-22/`。 |
| `work/` | 批次工作区。`work/<batch_id>/` 含 `receipt.json`（OCR 批次回执）、`ocr/`（每路每次尝试）、`audit/a<N>/`（第 N 次审计：对齐结果、`confirm.html`、小图 `crops/`）、`pipeline/`（阶段回执）、`med_intake.json`。`work/<yyyymmdd>` 是指向批次目录的日期别名。 |
| `confirm/` | 确认页入口。`confirm/<yyyymmdd>.html` 链接到最新确认页；要看到小图，打开 `confirm/<yyyymmdd>/confirm.html`。 |
| `_masked/` | 抬头打码后的图，**只有这里的图才能发给云端路**；带登记清单。 |
| `_mask_review/` | 打码对照图，给人核对用，永不外发。 |
| `_private/` | 私有密钥与映射（例如脱敏用的密钥），不入库、不外发。 |
| `records/` | 记录。`records/_by_id/` 每条记录一个文件，`records/_rev/` 每个修订的正文（写一次、只读），`records/<日期>-<类型>.md` 是只读视图。 |
| `verified/` | 只链接有效且已确认（verified）的记录视图。 |
| `kb/<库名>/` | 知识库。`builds/<构建号>/` 是不可变构建（完成后整棵只读，含 `library/`、`cards_content/`、`build_receipt.json`、`check_receipt.json`、`MANIFEST.sha256`）；`current`（即 `kb/<库名>/current/`）是指向已发布构建的相对符号链接；`PUBLISH.log` 只追加；`builds/_trash/` 是被清理的旧构建；`.readers/` 是读者租约。 |
| `kb/<库名>/src/` | 该库的书桌与留出集等输入（例如 `kb/<库名>/src/desk.json`）。属私有侧，不对外发布。 |

## 5. `tests/`

测试按「lane」分目录。lane 的含义和命令见 `README.md` 的「开发与测试」。

| 目录 | lane | 内容 |
|---|---|---|
| `tests/unit/` | `unit` | 纯函数、schema、HTML 结构、钩子、静态检查。不联网，无真实模型调用。 |
| `tests/contract/` | `contract_replay` | 契约样本、来源链往返、用回放录制重放的端到端链路。不联网。 |
| `tests/cli/` | `cli_integration` | 真实进程：启动器、klode / klode-mcp、pdftotext、本机 OCR 引擎、node。缺依赖就失败，不跳过。 |
| `tests/model/` | `model_integration` | 真实模型调用（只用合成图）。需要闸门 G2 的授权。 |
| `tests/host/` | `host_acceptance` | `claude -p --plugin-dir .` 的宿主验收。需要闸门 G2 的授权。 |
| `tests/replay/` | `contract_replay` 的重做场景 | 重做 OCR 后旧的 verified 记录保持有效。 |
| `tests/acceptance/` | 每个文件自带 lane 标记 | U1–U8 用户感知层验收（WI-31）：只走用户入口，断言落在 stdout、退出码、生成文件和确认页数据块上；`*_real.py`、`*_host.py`、`*_qa.py` 是真实模型 / 宿主用例（需要闸门 G2）。 |
| `tests/docs/` | `unit` | 文档测试：三张工作流图的结构，以及文档引用的命令和路径都真实存在。 |
| `tests/fixtures/` | | 合成样本与生成器（`fx-*` 目录，`MANIFEST.json` 登记每个文件的 sha）。全部是虚构数据。 |
| `tests/recordings/` | | 各引擎的回放录制（合成页），按 `<引擎>/<衍生图 sha>.json` 存放，带独立 `MANIFEST.json`。 |
| `tests/_support/` | | 测试共用的辅助模块。 |
| `tests/fakes/` | | 假的 `claude` / `codex` 可执行文件，测试时放在 PATH 前面。 |
| `tests/conftest.py` | | 共用夹具；把 registry 指向临时文件，使任何测试都碰不到真实的 `~/.klode`。 |

## 6. 命名约定

- `skills/<名字>/SKILL.md` 的 `name` 决定命令：`/klode-kit:<名字>`；没有别的命令占用时，短名 `/<名字>` 也能用（详见 `docs/install.md`）。
- 构建号、批次号都是内容哈希，不是时间戳；日期别名只是方便人找。
- 「移动优先于删除」：清理一律进 `_trash/`（仓库）或 `builds/_trash/`（知识库）。
